# 原型最终行为与验收矩阵

本文件来自开始开发时对 [AGENTS.md](../../AGENTS.md)、[设计文档](../../人力资源平台一期开发设计-V1.0.0.md) 全部 DDL 与补充章节、当时为空且仅计划放前端的 `D:\5-HR\HR_system` 目录、原型业务脚本的审查。现有目录结构已调整：`D:\5-HR\HR_system` 是完整系统根，前端在其 `frontend`、后端在其 `backend`；这不改变原审查事实。

[原型文件](../../人力资源平台原型-v1.html) 仍位于 `D:/5-HR/人力资源平台原型-v1.html`，以下行号以未移动的原始文件为准。本文件是实现与验证清单，不代表相应功能已经通过验收；当前真实测试结果以 [修复复测报告](fix-regression-2026-09-23.md) 为准，原先三个导入缺陷已完成修复和定向验证。启动与目录对应关系见 [系统 README](../README.md)。

用户本次明确要求优先：Vue 前端、Java 后端、本地 MySQL、独立登录；`admin` / `manager` 手动登录，登录页没有账号提示和快捷登录，系统没有切换视角按钮；权限与数据范围由后端决定。原型本身没有登录页，其角色切换及演示主管部门选择器必须移除。

### 3.4 职级体系 `/grades`

最终依据：3556、3572、3585、3589、3624–3630、4048–4055。

列表字段：职级编码、名称、职务序列、对应层级、适用组织、状态。支持序列筛选、名称编码搜索、高级筛选、新增、导入、导入记录、导出、列配置；右上职级图谱/列表视图切换。图谱按层级降序、序列分列，点击职级进入编辑。

新增/编辑字段为序列、编码、名称、层级、适用组织、参考经验年限、状态、任职要求；详情可编辑或删除。管理职务序列支持新增、重命名、删除，重命名同步职级，有引用不能删除。已有员工职级不能无条件换序列、删除或停用；层级为正数、年限非负，适用组织变更不得使既有员工落出范围。岗位最终不再与职级建立关联。

### 3.5 基础信息设置 `/settings`

最终依据：5161–5227。

三个页签工作片区、工作所在地、合同归属，各显示数量。表格为序号、名称、状态、引用记录、操作。按钮：查询、重置、新增当前字典、编辑、启用/停用、删除。新建/编辑只有名称；名称1–80字符，不得与名称或历史别名冲突。重命名同步既有引用并保存旧名称作为导入别名；有引用不能删除；停用值历史查询仍可见，新增不能使用。字典独立，不擅自建立片区→工作所在地父子限制。

正式初值：工作片区上海/南京；工作所在地上海/南京/宁波/西安/长沙/郑州/诸暨；合同归属微间/旦尺/方之达/佛豪斯/宁波舜变/青衿智创/上海数寰/上海有间/致臻/中数求索/中数求索（外包）/中数信息。

### 3.8 简历筛选 `/screening`

最终依据：3620–3623、5015–5101。

### 3.10 入职管理 `/offers`

## 5. 不应迁入生产的演示实现

1. `DB`内存数组、`uid()`随机时间ID、固定`TODAY=2026-09-18`、前端校验充当唯一权限、`URL.createObjectURL`充当长期文件存储。应分别换为服务端资源、数据库主键、可测试时钟、后端RBAC、持久文件服务。
2. 最早的“研发中心/产品研发部”等组织、虚构员工/候选人/资产、DEMO证件账号、虚构主管和`demo:部门:名字`面试官。开发库可显式演示种子，生产只导入真实组织与字典及授权初始账号。
3. 模板职位到组织的正则猜测、默认编制1、`T2-6`序列层级猜测，源代码明确“演示匹配，待HR核对”。生产不把猜测当企业事实。
4. “仅本次演示”“刷新恢复”“钉钉未接入”等内存提示应改为准确持久化说明；没有接入的外部通知只显示真实连接状态，不模拟成功发送。
5. 旧Offer/审批、面试五维打分、岗位职级/序列/地点、早期物理删员工均已被后置补丁覆盖，不作为最终UI。
6. `HRLegacyBridge`仅局部替换数据且强制hr；不迁移整页HTML/iframe再套Vue。正式前端必须由Vue响应式状态、组件、路由和API驱动。
7. 原型的局部瑕疵不能削弱已明确业务约束：招聘统计直接读全量DB、入职整体替换丢失需求自动完成、导入允许重复手机号而DDL唯一、公共资产使用中与DDL CHECK冲突、firstContractStart/contractStart别名混用，均需在后端规范化并测试，不复制漏洞。

## 6. Vue 提取方案与完成证据

最稳妥的提取方式是完整保留CSS顺序及类名，将内嵌字体/图标/Logo转成静态资源引用；抽取最终路由元数据、最终字段配置、58列表头和真实字典为声明式常量。构建 `AppShell`、`DataTable`、`ListFilters`、`ColumnSettings`、`AdvancedFilters`、`Drawer`、`OrganizationTree`、`ImportWizard` 等共享Vue组件，再按模块定义列表schema与表单。使用Vue事件与响应式数据，禁止从原型字符串拼接HTML后`innerHTML`驱动业务，也不要保留全局ACTIONS和MutationObserver控件桥接。

验证先覆盖两账号登录、菜单与跨部门读写拒绝、员工新建/编辑/归档恢复、58列导入及空值不覆盖、HR→部门筛选→初复试→入职闭环、岗位/需求编制、资产持有阻止离职及归还后离职、字典改名/停用/引用删除限制。并发至少验证同候选重复入职、同轮重复面试、旧版本员工/资产修改409。

像素级完成证据应包含相同视口、相同数据、同一浏览器的原型与实现截图：11模块默认页、代表性详情/编辑抽屉、列配置、高级筛选、未保存确认、展开筛选、员工全屏、面试结果与入职处理；等待字体就绪后比较布局、字体、颜色、间距、行高、固定列和浮层。只有真实业务及视觉验证通过后才可称为完整交付。
